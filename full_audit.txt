## 1. Честный вердикт: готов ли проект к релизу?

### ❌ **ОТВЕТ: К РЕЛИЗУ НЕ ГОТОВ (RELEASE NOT READY — NO-GO)**

Кодовая база верхнего уровня Flutter (UI-экраны, верстка, провайдеры состояния, тесты) выполнена на высоком уровне:
- `flutter analyze` завершается с **0 предупреждений и 0 ошибок**;
- `flutter test` проходит **58 из 58 тестов**;
- Архитектура Clean Architecture / Domain Models хорошо структурирована.

**Однако проект категорически нельзя выпускать в App Store и Google Play прямо сейчас из-за критических блокеров (P0) и функциональных разрывов с BLE-оборудованием (P1):**
1. **На машине разработчика полностью исчерпан диск `C:\` (0 байт свободно)** — R8/D8 упал с ошибкой `java.io.IOException: Недостаточно места на диске`.
2. **Проект Android настроен на debug-подпись** и не имеет настроенного Release Keystore и правил ProGuard для сжатия.
3. **Отсутствует обязательная зависимость `net.jpountz.lz4:lz4:1.3.0`** (требование Раздела 1.1 официальной документации): без неё любые функции передачи циферблатов вызывают фатальный краш.
4. **В `AndroidManifest.xml` отсутствует ключ производителя `YCAPPKEY`** (Раздел 1.3): облачные функции часов (AGPS, OTA, AI) отклоняются сервером производителя.
5. **В Android нет `NotificationListenerService`**: часы **вообще не получают push-уведомления и звонки** со смартфона на Android.
6. **Разрыв синхронизации сна и тренировок**: на Android вызывается кеш `getSciSleepData()` вместо протокольного `syncSleepHistoryData()`, а история тренировок (`syncWorkoutHistoryData` на Android и `getRecordList` на iOS) просто игнорируется.
7. **Ряд настроек в `DeviceSettingsScreen.dart` — фантомы**: переключатели "Умный будильник", "Напоминание о воде", "Анти-потеря" меняют локальное состояние виджета, но не отправляют команды в BLE-чип часов.

## 3. Детальный разбор критических проблем (P0 и P1)

### 🔴 P0.1. Физический блокер сборки: Переполнение диска `C:\`
При попытке сборки Android через Gradle возникла системная ошибка:
```text
Caused by: com.android.tools.r8.internal.g: java.io.IOException: Недостаточно места на диске
Execution failed for task ':app:mergeExtDexDebug'.
```
Проверка `Get-PSDrive C` показала:
- **Использовано:** `475.85 GB`
- **Свободно:** `0.00 GB (0 байт!)`

> **Что делать:** Вам необходимо освободить минимум **5–10 ГБ** на диске `C:\` (удалить временные файлы, кеши старых Gradle-демонов, неиспользуемые эмуляторы в `C:\Users\KPK\.android\avd\`). Без свободного места компилятор DEX и R8 физически не могут скомпоновать APK.

---

### 🔴 P0.2. Несовместимость версий AGP, Kotlin и лимиты памяти Gradle
1. **Проблема версий:** Библиотека `firebase_auth:24.2.0` скомпилирована с метаданными Kotlin 2.3.0/2.2.0, а в `settings.gradle.kts` был указан устаревший Kotlin `2.1.10`, а также старый AGP `8.7.3`, вызвавший конфликт с `androidx.core:core-ktx:1.18.0`.
   - *Что мы исправили в этой сессии:* В [`settings.gradle.kts`](file:///c:/Users/KPK/StudioProjects/untitled1/android/settings.gradle.kts#L20-L25) подняли `com.android.application` до `8.9.1` и `org.jetbrains.kotlin.android` до `2.2.0`.
2. **Строгая проверка типов в Kotlin 2.2:** Компилятор выявил несоответствия nullability в [`KalkanBleManager.kt`](file:///c:/Users/KPK/StudioProjects/untitled1/android/app/src/main/kotlin/com/yc/nadalsdk/barys_biotracker/KalkanBleManager.kt):
   - Строка 133: `UteBleClient.initialize(appContext)` требовал non-null `Context` вместо `Context?`. *(Исправлено)*
   - Строка 209: `mainHandler.postDelayed(nativeReconnectRunnable, delayMs)` требовал non-null `Runnable`. *(Исправлено)*
3. **Падение JVM по OOM:** В [`gradle.properties`](file:///c:/Users/KPK/StudioProjects/untitled1/android/gradle.properties) были выставлены завышенные параметры `-Xmx8G -XX:MaxMetaspaceSize=4G` (суммарно 12 ГБ), что приводило к падению JVM `G1 virtual space mmap failed` на машине с 15 ГБ ОЗУ. Мы оптимизировали параметры до стабильных `-Xmx3G -XX:MaxMetaspaceSize=1G`.

### 🟠 P1.1. Баг синхронизации научного сна на Android (Раздел 2.41)
В [`KalkanBleManager.kt`](file:///c:/Users/KPK/StudioProjects/untitled1/android/app/src/main/kotlin/com/yc/nadalsdk/barys_biotracker/KalkanBleManager.kt#L701-L706):
```kotlin
private fun pullNightAndDay() {
    // ВЫЗЫВАЕТСЯ ТОЛЬКО КЕШ:
    val sciData = uteBleConnection?.getSciSleepData()
    // ...
}
```
Согласно разделу 2.41 спецификации, метод `getSciSleepData()` возвращает только последний сеанс, временно удерживаемый в оперативной памяти чипа.
Чтобы вычитать данные сна из флеш-памяти часов, необходимо инициировать активную синхронизацию:
```kotlin
uteBleConnection?.syncSleepHistoryData(startTime, endTime)
```
и слушать колбэк получения пакетов сна. В iOS (`AppDelegate.swift`) этот метод реализован качественно (`getSciSleepModelWithStartTime`), а в Android — только чтение in-memory кеша.

### 🟠 P1.2. Потеря истории тренировок (Раздел 2.42 Word & iOS `pullWorkoutRecords`)
1. **На Android:** Метод `uteBleConnection?.syncWorkoutHistoryData(...)` вообще не вызывается. Тренировки, записанные пользователем автономно на часах, никогда не переносятся в телефон.
2. **На iOS:** В [`AppDelegate.swift`](file:///c:/Users/KPK/StudioProjects/untitled1/ios/Runner/AppDelegate.swift#L998-L1005):
```swift
private func pullWorkoutRecords() {
    guard isConnected else { return }
    let now = Int(Date().timeIntervalSince1970)
    let start = now - 24 * 3600
    device.getRecordList(start, endTime: now) { _, _, _ in }
}
```
Блок `{ _, _, _ in }` пустой! Вызов делается лишь для того, чтобы часы сняли флаг уведомления 0x08, но сами данные тренировки не парсятся и выбрасываются в никуда.

### 🟠 P1.3. Привязка аккаунта HUID и сброс устройства (Раздел 2.4, 2.5, 12.5)
В протоколе часов реализована защита от кражи и многопользовательской привязки:
- Если часам не передать валидный `currentHuid`, при повторном подключении или после смены телефона часы сообщают `ACCOUNT_DIFFERENT (1)`.
- Часы отображают на экране диалог подтверждения сброса и шлют событие `NotifyType.DEVICE_RESET_NOTIFY`.
- В [`KalkanBleManager.kt`](file:///c:/Users/KPK/StudioProjects/untitled1/android/app/src/main/kotlin/com/yc/nadalsdk/barys_biotracker/KalkanBleManager.kt) событие `DEVICE_RESET_NOTIFY` не обрабатывается.
- Если привязка аккаунта не требуется вашему продукту, документация требует явно вызвать при инициализации:
  ```kotlin
  mUteBleConnection.setSupportUserIdPair(false)
  ```
- При логауте пользователя в приложении (`UserSessionManager`) ни на Android, ни на iOS не вызывается `clearAccountID()` / `sendDeleteAccountInformationBlock` (см. эталон в `DeleteAccountInformation.txt`).

## 4. Конкретный пошаговый план устранения для допуска к релизу

```mermaid
graph TD
    A[1. Освободить диск C: минимум 5 ГБ] --> B[2. Добавить LZ4 и YCAPPKEY]
    B --> C[3. Добавить NotificationListenerService в Android]
    C --> D[4. Настроить Keystore и Release ProGuard]
    D --> E[5. Исправить syncSleepHistoryData в Android]
    E --> F[6. Сохранить тренировки в SQLite/Firestore]
    F --> G[7. Привязать переключатели DeviceSettings к SDK]
    G --> H[8. Финальный релизный билд AAB / IPA]
```

### Шаг 1: Очистить диск `C:\`
Удалить временные файлы и неиспользуемые файлы сборки, чтобы на диске `C:\` появилось минимум **5–10 ГБ** свободного места.

### Шаг 2: Добавить обязательную зависимость LZ4 в `android/app/build.gradle.kts`
```kotlin
dependencies {
    implementation(fileTree(mapOf("dir" to "libs", "include" to listOf("*.aar", "*.jar"))))
    implementation("com.google.code.gson:gson:2.8.6")
    implementation("androidx.core:core-ktx:1.13.1")
    implementation("net.jpountz.lz4:lz4:1.3.0") // <-- Добавить обязательно
}
```
И в `android/app/proguard-rules.pro` добавить:
```proguard
-keep class net.jpountz.** { *; }
```

### Шаг 3: Добавить ключ вендора `YCAPPKEY` в `AndroidManifest.xml`
Запросить у производителя ваш рабочий App Key и прописать в `<application>`:
```xml
<meta-data
    android:name="YCAPPKEY"
    android:value="ВАШ_КЛЮЧ" />
```

### Шаг 4: Реализовать `KalkanNotificationService` на Android
Создать сервис, наследующий `NotificationListenerService`, зарегистрировать его в `AndroidManifest.xml` с разрешением `android.permission.BIND_NOTIFICATION_LISTENER_SERVICE`, и вызывать:
```kotlin
val msg = MessageInfo()
msg.type = resolveAppType(sbn.packageName)
msg.content = sbn.notification.extras.getString(Notification.EXTRA_TEXT) ?: ""
uteBleConnection?.sendMessage(msg)
```

### Шаг 5: Переключить чтение сна на протокольный `syncSleepHistoryData` в `KalkanBleManager.kt`
Заменить пассивный `uteBleConnection?.getSciSleepData()` на активный запрос архива сна за последние 48 часов:
```kotlin
uteBleConnection?.syncSleepHistoryData(startTimeSec, endTimeSec)
```
и обрабатывать входящие пакеты в колбэке.

### Шаг 6: Настроить релизную подпись (Release Keystore)
Создать keystore файл (`key.properties`), настроить `signingConfigs.create("release")` в `android/app/build.gradle.kts` вместо использования `signingConfigs.getByName("debug")`.

### Шаг 7: Связать переключатели в `DeviceSettingsScreen.dart`
Подключить вызовы MethodChannel к:
- `setDisconnectRemind` (оповещение о разрыве);
- `setAlarmList` (будильники);
- `setWaterClock` (напоминание о воде по спецификации `Water reminder.txt`).
